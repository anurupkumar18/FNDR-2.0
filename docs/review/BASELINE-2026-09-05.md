The legacy repository proves several end-to-end concepts but carries the
audited structural liabilities that FNDR-2.0 is designed to avoid. No legacy
module is copied wholesale. Every approved port must satisfy ADR-005 with a
source commit, narrow provenance note, tests, known-defect review, and an
explicit exclusion list.

## Preserved work outside the dirty donor checkout

The legacy checkout contained one uncommitted pre-OCR sensitive-context guard.
It has been preserved without modifying that checkout in the isolated branch
`codex/p002-sensitive-preocr` at commit `4f48ae46`. Its regression test proves
that password-manager, banking, and login contexts are skipped with an empty
user blocklist while an ordinary VS Code context is retained.

This branch is a reviewed donor patch, not an authorization to merge legacy
capture architecture into FNDR-2.0. A future v2 port must first place the
policy data and replay coverage in the v2 privacy/capture contracts.

## Alpha merge rule

An alpha change is eligible only when it:

1. lands in FNDR-2.0, not the legacy mainline;
2. maps to a PRD requirement and a roadmap ticket;
3. obeys the five FNDR-2.0 invariants, especially local default and
   port-provenance requirements;
4. has a focused regression or contract test; and
5. reports the relevant verification result and known environmental limit.
